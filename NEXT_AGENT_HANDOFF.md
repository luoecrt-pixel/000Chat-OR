# NEXT_AGENT_HANDOFF

Область этого форка — OpenRouter/Claude. Старые OpenAI сообщения, checkpoint, usage и локальные файлы читаются без сетевого исполнения OpenAI. Не удаляй их формат или fingerprint v1 вместе с транспортом и не возобновляй оплаченный запрос через другой API. Установка форка изолирована отдельным applicationId от исходного 000Chat.

1. Выполняй последнее поручение владельца в согласованных границах. Перед правкой сверяй актуальные код, main и PR; старые планы, патчи и результаты другого SHA не доказывают текущее состояние. Toolchain и версии сверяй по build/workflows. Main изменяй через PR, если владелец прямо не поручил иное; не перезаписывай чужие изменения и не делай force-push вслепую.

2. До реализации определи требуемое изменение, его потребителей и возможные отказы. Выбери решение с наименьшим вмешательством в остальные контракты; массовый рефакторинг — отдельный scope. При замене общего механизма проверь также ошибки, отмену, атомарность и освобождение ресурсов. Сохраняй поведение вне цели задачи.

3. Асинхронный результат применяй после проверки относящихся к нему chat/request/generation/item, аккаунта и lifecycle; UI меняй в main thread, после onStart восстанавливай актуальное состояние. Stop/Delete/switch/recreate/Worker не должны оживлять старый запрос. Необязательная работа запускается только при применимости и не задерживает основной интерфейс.

4. Сохраняй полный текст, все исторические вложения и originals, порядок сообщений, порядок и подписи reasoning/tool replay, drafts, fingerprint v1 и request-aware SQLite CAS. Производная копия не заменяет original/wire source; server file IDs не переходят между аккаунтами. Большие SQLite TEXT читай через SqliteLargeTextQuery, включая транзакции, без маскировки ошибок схемы.

5. Различай raw usage ответа, сумму цепочки OpenAiUsageLedger и прежнюю неразмеченную legacy-базу; агрегат не становится raw дочернего ответа и не начисляется повторно. Неподтверждённый расход — unknown. Checkpoints удаляй после owner-aware terminal/Stop commit; оплаченный output сохраняй в recovery archive без восстановления удалённых сообщений.

6. Не вводи скрытые усечения, автоматические платные повторы, молчаливое снижение выбранного effort, короткие idle timeout, fixed tool rounds или неявный max_output_tokens. OpenAI Responses recovery и OpenRouter inference не взаимозаменяемы. Аварийные пределы: 5 часов на response/recovery, дополнительно 5 млн reported usage tokens на complete/tool-loop cycle OpenRouter; это не предел истории/сеанса. Файловые byte/page budgets дают явную ошибку; cache-маркеры 1h/5m не конфликтуют.

7. Не ослабляй TLS, SHA pins, JSON/SSE и EXIF/JPEG проверки, redaction, GitHub allow-list и подтверждения записи ради исправления или тестов. Статическое HTML/SVG-превью остаётся без JS/сети/Android bridge; научный renderer исполняет доверенные SHA-pinned offline-assets под app-owned HTTPS/CSP; код модели допускается только в отдельно и явно запускаемой изолированной песочнице без доступа к приложению и сети. Соблюдай [SECURITY.md](SECURITY.md), [NOTICE.md](NOTICE.md) и [RENDERER_DISTRIBUTIONS.md](RENDERER_DISTRIBUTIONS.md).

8. Механизм ошибки доказывай воспроизведением или однозначным кодом. Проверяй наблюдаемый результат на простейшем уровне, воспроизводящем Android/SQLite/Worker/HTTP: отказ старого пути, успех исправления и опасный соседний эффект; для нового поведения — обычный сценарий и существенную границу. Для гонок управляй событиями; не копируй алгоритм в тест. Вывод должен соответствовать фактическому доказательству; неизвестное обозначай явно.

9. Сначала выполняй целевые проверки, затем tools/verify_handoff.py, tools/verify_v4_17_0.py, tools/verify_implementation.py и релевантные mutation checks. Для code/test/build изменений нужны успешные push Debug/Release соответствующего code SHA: полный job включается через [ci] или CI_AUTO_RUN; skipped/cancelled не означают success. Для docs-only после проверенного code SHA нужны структура, ссылки и Verify handoff финального head, без Android rebuild. Сверяй event/SHA/attempt/conclusion и причину отказа. Расширяй проверку только при новом изменении, сбое или конкретном неразрешённом риске; не маскируй сбой увеличением ожидания.

10. Сдавай связанные проверяемые PR с итоговым diff и коротким доказательством «контракт → runtime path/тест → фактический уровень проверки → SHA/CI», отдельно отмечая live/device/billing границы. Назначенный независимый аудитор проверяет готовые PR; Draft — только адресно по поручению, без полного аудита каждого коммита. После исправлений проверяй delta и затронутые зависимости, перед решением — итоговый PR; различай регрессию, прежний backlog и неподтверждённый риск. Draft → Ready и squash merge требуют поручения владельца на конкретный PR; перед merge повторно сверяй main, независимое заключение, проверки и ожидаемый HEAD. Существенный неразрешённый риск данных, безопасности или цены блокирует merge. Телефон, платные API, публичность, подписывающие ключи и публикация требуют отдельного разрешения.

**Для независимого аудитора — качество реализации.** Помимо результата проверь изменённый runtime-путь: устранена ли первопричина, не подменена ли она частным обходом общего контракта; нет ли дублирования логики/состояния, скрытых fallback и подавления ошибок, хардкода, тестовых исключений или неоправданной сложности. Оцени соседние сценарии и более простые альтернативы. Локальный workaround допустим, когда его необходимость, границы и проверки обоснованы; не требуй несвязанного рефакторинга ради стиля. Существенный недостаток фиксируй с `file:line`, механизмом риска и необходимым изменением; неподтверждённые подозрения не объявляй блокерами. В заключении не пересказывай очевидное и уже известное: сообщай новые существенные выводы, а при их отсутствии — кратко фиксируй это без банальных подтверждений.

11. Информационные файлы создавай и дополняй в согласованном объёме поручения; уже порученная документация не требует повторного согласования. Не создавай лишние отчёты и журналы. В handoff сохраняй устойчивые правила, текущие SHA/CI и результаты — в PR без секретов и необработанных логов. Из единственного плана [AGENT_TASKS.md](AGENT_TASKS.md) удаляй только доказанно выполненное, не добавляя идеи агента. [PROJECT_HISTORY.md](PROJECT_HISTORY.md) — не журнал действий: читай по необходимости, изменяй в согласованном объёме ради существенной неочевидной причины. До окончания рабочего окна сохрани код и передай точный остаток работы.
